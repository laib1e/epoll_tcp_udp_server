# Асинхронный TCP/UDP сервер на epoll

Сервер на C++20 для GNU/Linux, асинхронно обрабатывающий клиентские подключения по протоколам TCP и UDP с помощью механизма мультиплексирования на базе epoll. Без использования сторонних библиотек.

## Требования

- GNU/Linux
- GCC с поддержкой C++20 (`g++ 10+`)

## Сборка и запуск

```bash
make
./server
```

TCP слушает на порту 60000, UDP — на порту 60001.

## Использование

### Echo (зеркалирование)

Любое сообщение без `/` в начале возвращается клиенту:

```bash
# TCP
echo "hello" | nc localhost 60000

# UDP
echo "hello" | nc -u -w1 localhost 60001
```

### Команды

Сообщения, начинающиеся с `/`, интерпретируются как команды:

| Команда | Описание |
|---------|----------|
| `/time` | Текущая дата и время (`2025-11-10 17:28:45`) |
| `/stats` | Статистика: всего подключений и активных в данный момент |
| `/shutdown` | Корректное завершение сервера |

```bash
# TCP
echo "/time" | nc localhost 60000
echo "/stats" | nc localhost 60000
echo "/shutdown" | nc localhost 60000

# UDP
echo "/time" | nc -u -w1 localhost 60001
echo "/stats" | nc -u -w1 localhost 60001
```

## Архитектура

### Основные компоненты

**`Stats`** — структура состояния сервера. Хранит счётчики подключений, флаг работы и метод `process(std::string_view cmd)` для обработки команд. Используется `std::format` (C++20) для форматирования ответов.

**`TCP`** — класс TCP-сервера. Создаёт listener-сокет, управляет клиентскими подключениями через `std::vector<int>`. Метод `handle_event` различает события на listener (accept нового клиента) и на клиентском сокете (чтение, обработка, ответ или отключение).

**`UDP`** — класс UDP-сервера. Один сокет обслуживает всех клиентов через `recvfrom`/`sendto`.

**`EventLoop<T, U>`** — шаблонный event loop на epoll. Принимает два обработчика, удовлетворяющих концепту `TransportPolicy`. Маршрутизирует события через `owns(fd)` — каждый обработчик знает, какие дескрипторы ему принадлежат.

### Статический полиморфизм

Вместо виртуальных методов используется C++20 concept `TransportPolicy`:

```cpp
template<typename T>
concept TransportPolicy = requires(T t) {
    { t.fd() } -> std::convertible_to<int>;
    { t.owns(int{}) } -> std::convertible_to<bool>;
    { t.handle_event(int{}, std::declval<Stats&>(), int{}) };
};
```

`EventLoop` параметризован типами обработчиков — все вызовы разрешаются на этапе компиляции (zero-cost abstraction).
